# Adapter interfaces — Codex fallback after Gemini authentication failure
Gemini CLI failed authentication (HTTP 401) before generating code. These adapters are implemented by a Codex subagent, not Gemini output.

All connectors are constructor-configured; none import environment variables, Prisma, queues, or domain state. They make no network calls on import. External writes require `writesEnabled: true`; no connector retries uncertain writes. Caller must persist an operation as `started` before invocation, keep a distributed per-expediente lock, and invoke with `reconcileOnly: true` after any crash/timeout. An uncertain outcome is never safe to retry blindly.

- `src/adapters/whatsapp/webhook-router.ts`: `verifyWebhookSignature(raw: Buffer, signature: string|undefined, appSecret: string): boolean`; `verifyWebhookChallenge(query, verifyToken): string|null`; `normalizeWebhook(payload: unknown, expectedPhoneNumberId: string): {messages: WhatsAppInboundMessage[]; statuses: WhatsAppStatus[]}`. Normalized messages contain id/from/timestamp/type, optional media metadata, contextId, and allowlisted buttonId. Freeform text, captions, filenames, contact names and passwords are discarded. `textPresent` indicates a human should inspect through a separately authorized secure channel. No API marks anything read.
- `WhatsAppClient(options)` (`accessToken`, `phoneNumberId`, `apiVersion`, `writesEnabled?`, `mediaHosts?`, `maxMediaBytes?`, `timeoutMs?`). `sendText(to, text)`, `sendButtons(to, body, buttons)`, `sendTemplate(to, name, languageCode, parameters?)`, `sendDocument(to, mediaId, filename?)` return `{messageId, accepted:true}`; acceptance is not delivery. `downloadMedia(mediaId, {expectedSha256?, allowedMimeTypes?})` returns `{content:Buffer, sha256, mimeType}`. `uploadMedia(content,mimeType,filename)` returns media id. Persist a started outbound action before sending; Meta has no assumed idempotency guarantee.
- `KmaleonClient(options)` (`baseUrl`,`clientId`,`clientSecret`,`authState`,`redirectUri`,`writesEnabled?`,`timeoutMs?`,`authTimeoutMs?`), `invokeRead(method,payload)`, `invokeWrite(method,payload)`. HTTPS only; known read and write allowlists. No email endpoints.
- `KmaleonGateway(client, options)`: required `recipientCode` and reviewed `mapping` with response parsers (`projectIdentity`, `annotationsPage`, `documentBytes`). `uploadAndVerifyDocument({projectId,expectedDni,buffer,fileName,idempotencyKey,isProvisional,reconcileOnly?})` returns `{verified:true,projectId,annotationId,documentId,sha256,idempotencyKey}` only after project identity, exact annotation reference and retrieved bytes SHA256 agree. `notifyCarmen({projectId,expectedDni,idempotencyKey,documentProof,isProvisional,reconcileOnly?})` returns a verified annotation proof after re-read of exact recipient/text/project. Gateway has three bounded readback attempts and rejects ambiguous duplicate matches. No defaults for staff identifiers or unverified vendor response shapes.
- `ApudataClient(options)` requires explicit HTTPS base URL, bearer token, writesEnabled and `reviewedMapping` (paths, request builders, response parsers). `preapprove`, `findOrder`, `createOrder` perform real configured HTTP; no default provider domain. `ApudataGateway(client, approvedPayment)` requires approved IBAN, currency EUR, amount cents, and evidence reference. `buildPaymentInstruction(approval, expectedClientId)` validates approval ID, client ID, true preapproval, expiry, and evidence, then emits instructions. `createOrder({clientId,idempotencyKey,approval,paymentEvidenceRef,reconcileOnly?})` reconciles before any write. `verifyApudataCallback(raw,timestamp,signature,secret)` implements only the deployment-reviewed APOD callback format: HMAC-SHA256 over timestamp + '.' + raw bytes, max five minute skew. Provider must support that format or a reviewed replacement is required. Persist callback event ID uniquely.
- `SedePlaywright(options)` accepts a reviewed official-origin draft recipe. `prepareDraft({clientId,expectedDni,consent,certificate:{pfx,passphrase},fields})` creates a nonpersistent context with in-memory client PFX, restricts network to reviewed official origins, runs only reviewed draft steps, returns `{status:'DRAFT_REQUIRES_HUMAN_SUBMISSION',pdf,sha256,recipeId}`. Never signs/submits/revokes. No shipped selectors claim live verification. Caller certificate inspector must bind DNI, validity and key possession before calling, and caller must never persist certificate/password.

Operational dependencies still unavailable: actual WhatsApp account configuration and approved template IDs; reviewed Kmaleon response shapes and Carmen recipient code; real Apudata API/domain, callback specification, preapproval/payment terms and approved account; reviewed Sede draft selectors and official network origins. Browser and JS runtime may retain copies of immutable password strings; best-effort buffer zeroization is not provable RAM erasure. Run certificate-assisted jobs in short-lived isolated processes.

Protocol sources: local existing Kmaleon client read-only; [Meta-owned Cloud API collection](https://www.postman.com/meta/whatsapp-business-platform/documentation/wlk6lh4/whatsapp-cloud-api), [Meta webhook SDK](https://whatsapp.github.io/WhatsApp-Nodejs-SDK/api-reference/webhooks/start/), [Playwright browser contexts/client certificates](https://playwright.dev/docs/api/class-browser).

## Runtime wiring and exact configuration schemas
`loadConfiguredAdapters(values: Record<string,string|undefined>)` from `src/adapters/configured.ts` reads `KMALEON_CONFIG_FILE`, `APUDATA_CONFIG_FILE`, and `SEDE_RECIPE_FILE`. Call it with the process environment, which includes custom credential variable names. It returns `{kmaleon?: KmaleonGateway, apudata?: ApudataGateway, sede?: SedePlaywright}`. Files must be reviewed JSON, at most 128 KiB, with `reviewed: true`, a nonempty `reviewEvidenceRef`, and explicit `enabled`. An adapter writes only when its file has `enabled: true` **and** `OUTBOUND_ENABLED=true`. There are no active default mappings. Absent files omit the connector; malformed configured files fail startup.

The authoritative strict Zod schemas are in `src/adapters/configured.ts`; unknown keys are rejected. Dot paths refer to actual properties in vendor responses, use own properties only, and reject prototype-related segments. They cannot execute code, fetch arbitrary URLs, or fill missing identity from request values.

Kmaleon JSON keys:
- Review keys above, `baseUrl` HTTPS, `clientId`, `clientSecretEnv` (environment variable NAME), `authState`, `redirectUri`, `recipientCode` (actual Carmen staff code).
- `mapping.project: {id, dni}` with dot paths from the `projects/getProject` response.
- `mapping.annotations: {items, fields, pendingEncoding, hasMore? , totalRows?, pageSize?}`. `items` is a response-root dot path (empty string means root). `fields` contains paths relative to each actual row: `id`, `projectId`, `text`, `recipientCode`, `documentId`, `pending`. `documentId` must be a real property; null/empty is allowed for a notice. `pendingEncoding` is `boolean` or `opciones-P` for legacy flag strings. Require either a real boolean `hasMore` path, or an actual numeric `totalRows` path plus reviewed `pageSize`. The latter assumes actual zero-based page numbering and checks full nonfinal pages.
- `mapping.document: {base64}` points to the actual returned base64 content, not a filename or download URL. Responses that do not expose trustworthy project/DNI/document data need a reviewed mapping extension before use.

Apudata JSON keys:
- Review keys above, `baseUrl` HTTPS, `accessTokenEnv` (variable NAME), `payment:{iban,amountCents:3500,currency:"EUR",evidenceRef}`. Only a reviewed actual Spanish IBAN passing checksum is accepted. No account is supplied by this code.
- `mapping.preapprove`, `mapping.findOrder`, `mapping.createOrder`: each `{path, method:"GET"|"POST", body?}`. `path` may interpolate `{idempotencyKey}` or another allowed source using URI encoding. Body maps vendor dot-path fields to `{source:"SOURCE"}` or `{literal: primitive}`. Allowed sources: `clientId`, `dni`, `nombre`, `idempotencyKey`, `approvalId`, `approvalEvidenceRef`, `approvalExpiresAt`, `paymentEvidenceRef`, `amountCents`, `currency`. Each of the three calls must include `idempotencyKey`; the provider's real deduplication semantics still require review. The lookup endpoint must be read-only even if the provider uses POST.
- `mapping.approvalFields` has actual response dot paths for `id`, `clientId`, `preApproved` (boolean true), `expiresAt` (ISO timestamp), `evidenceRef`.
- `mapping.foundOrderRoot` and `mapping.createdOrderRoot` select result roots. Found order root may be null, empty array, single order array or an order object. More than one order fails closed. `mapping.orderFields` maps relative fields `id`, `clientId`, `idempotencyKey`, `approvalId`, `amountCents`, `currency`, `status`, optional `documentSha256`. Accepted statuses are `created`, `video_pending`, `document_ready`, `failed`; unknown vendor statuses require reviewed translation code. A failed order is never reported as successful.
- Exact preapproval call: `preapprove({clientId, dni, nombre?: string, idempotencyKey})`. It does not automatically retry. Order creation needs real operator-confirmed payment evidence bound to the client and approval. `buildPaymentInstruction(approval, expectedClientId)` is the only instruction renderer and rechecks approval expiry. `createOrder` permits read-only reconciliation of an existing order after approval expiry but prohibits a new order without current approval.

Sede JSON keys: review keys above and `recipe`, matching `SedeDraftRecipe` in the adapter. Recipe contains `id`, `reviewEvidenceRef`, `reviewedDraftOnly:true`, `officialOrigins`, `startUrl`, `allowedRequests:[{origin,pathname,method,purpose}]`, `steps`, `identitySelector`, `draftReadySelector`, `draftPdfLinkSelector`. `pathname` is exact, no wildcard. Purposes are `authentication`, `read`, `draft`. Steps: `{kind:"fill"|"select",selector,field}` or `{kind:"click"|"check"|"wait",selector}`. Fill/select values come only from the request `fields`. The authenticated page must expose one expected DNI **before** draft steps and after them. All selector/network effects require live human review before enabling the recipe; the code cannot infer whether a vendor endpoint is legally effective. No configured recipe is shipped. The allowed host suffixes currently cover justicia.gob.es and administracion.gob.es only; other official origins require a reviewed extension.

## Review and verification performed
Codex inspected these adapters without making external service calls. Corrected uncertain-outcome handling after Apudata response-mapping failures, rejected failed/mismatched provider orders, required explicit idempotency sources in every Apudata request, rejected Kmaleon reused references with changed content or recipient, and checked Sede authenticated DNI before draft interactions. Certificate buffers are zeroed on browser-launch failure as well as normal completion. Sede PDF download streams in RAM with a strict byte limit via Undici, uses only the reviewed HTTPS endpoint and session cookies, rejects redirects/non-PDF results, and never calls browser download/save APIs.

Remaining verification boundaries: no real provider credentials, reviewed payload captures, official draft recipe, actual client certificate, or real PDF was supplied to this subagent. Type checking does not establish live provider correctness, legal sufficiency, authentic signatures, payment receipt, message delivery or live filing. No mock/synthetic tests or real external writes were run. Potential browser/JS/OS memory copies of password/PFX cannot be proven erased; isolate certificate jobs in short-lived processes. Gateway callers remain responsible for durable started intents, lock ownership, atomic human-approval checks immediately before writes, and transactionally unique callback IDs.

Apudata order records now optionally expose `videoUrl`. The declarative `mapping.orderFields.videoUrl` path is optional. The live client admits a video URL only if it is HTTPS, contains no credentials/fragment, and exactly matches the configured provider origin. An absent link remains absent; the caller must hold for review rather than construct a guessed link. Sede browser WebSockets are blocked explicitly, and consent is checked again before fetching the PDF directly.

## Verified Kmaleon address retrieval

`KmaleonGateway.getVerifiedAddress({projectId: string, expectedDni: string})` is a read-only operation returning:

```ts
{
  projectId: string;
  dni: string; // normalized and checksum-validated DNI/NIE
  direccion: string;
  codigoPostal: string;
  provincia: string;
  localidad: string;
  comunidadAutonoma?: string;
  evidenceRef: string; // kmaleon-address:sha256:<digest>
}
```

Enable the method by adding optional `mapping.projectAddress` to the reviewed Kmaleon JSON configuration. Its required keys are `projectId`, `dni`, `direccion`, `codigoPostal`, `provincia`, and `localidad`; `comunidadAutonoma` is optional. Every value is an actual dot path from the `projects/getProject` response root. The `projectId` and `dni` paths must identify the client who owns the mapped address, as confirmed when reviewing the provider response. Array position alone is not identity evidence. Existing `mapping.project` identity paths are checked independently on the same response. No path defaults are shipped.

The gateway checks for the address mapping before making any network request, validates the expected Spanish DNI/NIE checksum, fetches the project once, and verifies both the project identity and mapped address-owner identity. Missing fields, nulls, arrays, blank/control-character text and a mismatched project or DNI fail closed. Only a real numeric project identifier may be stringified. Postal codes must be actual five-digit strings; leading zeroes are never inferred or padded. Text is trimmed and bounded; a configured but missing autonomous-community field also fails closed.

The evidence reference hashes the exact received JSON response, the mapping-review reference and the normalized address values. It identifies the source snapshot without exposing the response body in the reference. Persist the returned address and reference with the observation timestamp in the caller's audit record. The gateway does not infer the judicial district or establish that an address is current empadronamiento evidence; geographical resolution and the human district/address-sufficiency gate remain in the orchestrator.

Focused strict TypeScript compilation passed after implementation. No provider contact, external write, synthetic document or mock test was used to validate this change; actual response mapping and live address retrieval remain to be verified using an authorized real case.
